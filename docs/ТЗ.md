## на розробку системи SmartScreen

**Тема курсової роботи:** «Розробка системи інтелектуального аналізу екрана для автоматизації контекстних дій за допомогою штучного інтелекту»

**Версія документа:** 1.1  
**Дата актуалізації:** 16.05.2026  
**Статус:** production-oriented специфікація для курсової реалізації

> Примітка щодо платформи: локально в середовищі встановлено .NET 9 SDK, тому першу реалізацію доцільно починати з `net9.0-windows`. Для реального production-релізу варто передбачити простий перехід на .NET 10 LTS, оскільки .NET 10 має довший цикл підтримки, а .NET 9 є STS-версією. Джерело: офіційна політика підтримки .NET — https://dotnet.microsoft.com/en-us/platform/support/policy.

# 1. Загальні відомості

## 1.1. Найменування системи

Найменування програмного продукту: **SmartScreen**.

SmartScreen — portable desktop-застосунок для Windows 10/11, який дозволяє створювати скріншоти, швидко редагувати їх, копіювати, зберігати та виконувати інтелектуальний аналіз вмісту екрана через зовнішні AI API.

## 1.2. Призначення системи

Система призначена для користувачів, які часто працюють з інформацією на екрані: помилками, текстом, кодом, інтерфейсами, документами, повідомленнями та навчальними матеріалами.

SmartScreen повинен працювати як повноцінний скріншотер навіть без AI-налаштувань, а AI-функції мають бути додатковим шаром контекстної допомоги.

## 1.3. Мета розробки

Метою розробки є створення зручної Windows-утиліти, яка поєднує функції скріншотера, редактора зображень і AI-помічника для аналізу поточного контексту користувача.

## 1.4. Ключова ідея продукту

SmartScreen не просто зберігає зображення екрана, а допомагає виконувати контекстні дії:

* пояснити помилку;
* розпізнати текст;
* перекласти текст;
* пояснити код;
* описати зображення;
* знайти проблему в інтерфейсі;
* сформувати відповідь на основі скріншота;
* виконати користувацький prompt.

# 2. Межі реалізації

## 2.1. MVP для курсової роботи

У межах курсової роботи обов’язково реалізувати:

* WPF-застосунок з MVVM-структурою;

* збереження PNG/JPG;

* вікно AI-відповіді;

## 2.2. Бажані можливості

Якщо основний функціонал стабільний, можна додати:

* вибір конкретного монітора;
* скріншот із затримкою;
* розмиття та пікселізацію області;
* майстер першого запуску;
* тест підключення до AI-провайдера;
* імпорт додаткових мов через JSON;
* покращені повідомлення про помилки.

## 2.3. Не реалізовувати

У межах курсової версії не реалізовувати:

* історію всіх скріншотів;
* історію AI-запитів;
* автоматичну відправку скріншотів до AI без дії користувача;
* приховане збереження всіх зображень;
* автоматичне керування іншими програмами;
* автонатискання кнопок;
* автоматичне введення тексту в інші програми;
* фоновий моніторинг екрана.

# 4. Функціональні вимоги

## 4.1. Робота зі скріншотами

Система повинна підтримувати такі режими:

| ID | Вимога | Пріоритет |
| --- | --- | --- |
| SCR-01 | Скріншот всього екрана | Must |
| SCR-02 | Скріншот вибраної області | Must |
| SCR-03 | Скріншот активного вікна | Must |
| SCR-04 | Скріншот конкретного монітора | Should |
| SCR-05 | Скріншот із затримкою 3/5/10 секунд | Should |

Після створення скріншота система повинна:

* скопіювати зображення в буфер обміну, якщо це ввімкнено в налаштуваннях;
* відкрити повноекранний capture workspace (`QuickActionsWindow`) з напівпрозорим overlay;
* дозволити зберегти файл;
* дозволити відкрити редактор;
* дозволити виконати AI-запит;
* дозволити закрити скріншот без збереження.

## 4.2. Збереження скріншотів

Система повинна підтримувати:

* PNG;
* JPG/JPEG з налаштуванням якості;
* шаблон назви файлу `screenshot_yyyy-MM-dd_HH-mm-ss`;
* вибір папки збереження;
* перевірку доступності папки;
* fallback до директорії користувача, якщо portable-папка недоступна для запису.

За замовчуванням скріншоти зберігаються в:

```text
SmartScreen/screenshots/
```

## 4.3. Capture workspace і швидкі дії

`QuickActionsWindow` має працювати як єдиний повноекранний workspace поверх створеного скріншота. Базова панель швидких дій повинна бути компактною, напівпрозорою, не перекривати критично важливу частину зображення та відкривати редактор і AI без переходу в окремі вікна.

Обов’язкові дії:

* зберегти;
* скопіювати;
* редагувати;
* запитати AI;
* вибрати AI-дію;
* ввести власний prompt;
* відкрити папку збереження;
* закрити без збереження.

## 4.4. Редактор скріншотів

Редактор скріншотів повинен працювати з поточним скріншотом у пам’яті без окремого вікна: панель інструментів з’являється в capture workspace поверх зображення.

Обов’язкові інструменти MVP:

* олівець;
* лінія;
* стрілка;
* прямокутник;
* еліпс;
* текст;
* маркер;
* обрізання;
* undo;
* redo.

Бажані інструменти:

* розмиття;
* пікселізація;
* швидке приховування приватних даних.

Налаштування інструментів:

* колір;
* товщина лінії;
* розмір тексту;
* прозорість маркера.

Оригінал окремо не зберігається. У файл записується лише фінальна відредагована копія після явної дії користувача.

## 4.5. AI-модуль

AI-інтеграція має бути розширюваною через спільний інтерфейс:

```csharp
public interface IAiProvider
{
    string Name { get; }

    Task<AiResponse> AnalyzeImageAsync(
        AiRequest request,
        CancellationToken cancellationToken = default);

    Task<bool> TestConnectionAsync(
        AiProviderSettings settings,
        CancellationToken cancellationToken = default);
}
```

Основні моделі:

```csharp
public sealed class AiRequest
{
    public required byte[] ImageBytes { get; init; }
    public required string ImageMimeType { get; init; }
    public required string UserPrompt { get; init; }
    public string? SystemPrompt { get; init; }
    public required AiProviderSettings ProviderSettings { get; init; }
}

public sealed class AiResponse
{
    public bool Success { get; init; }
    public string? Text { get; init; }
    public string? ErrorMessage { get; init; }
    public TimeSpan Duration { get; init; }
}
```

Провайдери:

* `OpenAiCompatibleProvider` або `CustomApiProvider` — робоча реалізація MVP;
* `OpenAiProvider`, `GeminiProvider`, `ClaudeProvider`, `OpenRouterProvider` — окремі класи або адаптери, які можна доробити після MVP.

AI-запит виконується тільки після явної дії користувача.

## 4.6. Prompt-шаблони

Система повинна містити стандартні категорії:

* Загальні;
* Текст;
* Код;
* Помилки;
* Інтерфейс;
* Переклад;
* Користувацькі.

Стандартні AI-дії:

1. Що зображено на скріншоті?
2. Розпізнай текст.
3. Переклади текст українською.
4. Переклади текст англійською.
5. Поясни помилку.
6. Поясни код на скріншоті.
7. Знайди проблему в інтерфейсі.
8. Склади відповідь на основі скріншота.
9. Зроби короткий підсумок.
10. Поясни, що потрібно зробити далі.
11. Користувацький prompt.

Користувач повинен мати можливість додавати, редагувати, видаляти та відновлювати prompt-шаблони.

Файл збереження:

```text
config/prompts.json
```

## 4.7. AI-панель відповіді

AI-панель у capture workspace повинна підтримувати:

* показ тексту відповіді;
* стан завантаження;
* скасування запиту;
* копіювання відповіді;
* повтор запиту;
* зміну prompt;
* збереження відповіді у `.txt`;
* зрозуміле повідомлення про помилку.

AI-відповіді не зберігаються автоматично.

## 4.8. Гарячі клавіші

HotkeyService повинен підтримувати:

* глобальні гарячі клавіші;
* редагування комбінацій у налаштуваннях;
* перевірку конфліктів;
* збереження в `config/hotkeys.json`.

Стандартні комбінації:

| Комбінація | Дія |
| --- | --- |
| Ctrl + Shift + S | Скріншот області |
| Ctrl + Shift + F | Скріншот всього екрана |
| Ctrl + Shift + W | Скріншот активного вікна |
| Ctrl + Shift + A | AI-запит для поточного скріншота |

Швидка AI-дія дозволена тільки тоді, коли користувач явно налаштував відповідну гарячу клавішу.

## 4.9. Системний трей

TrayService повинен забезпечувати:

* іконку в системному треї;
* меню швидких дій;
* запуск у трей;
* згортання в трей;
* коректний вихід із програми.

Меню трею:

* зробити скріншот області;
* зробити скріншот всього екрана;
* зробити скріншот активного вікна;
* відкрити SmartScreen;
* налаштування;
* вийти.

## 4.10. Налаштування

SettingsWindow повинен мати вкладки:

1. Загальні.
2. Скріншоти.
3. Редактор.
4. AI-провайдери.
5. Prompt-шаблони.
6. Гарячі клавіші.
7. Інтерфейс.
8. Мови.
9. Безпека.
10. Логи.

Користувач не повинен редагувати JSON вручну для базових сценаріїв.

## 4.11. Мультимовність

Система повинна підтримувати:

* `uk-UA` як мову за замовчуванням;
* `en-US`;
* додавання нових мов через JSON-файли;
* fallback на українську, якщо ключ перекладу відсутній.

Файли:

```text
localization/uk-UA.json
localization/en-US.json
```

## 4.12. Теми

Система повинна підтримувати:

* світлу тему;
* темну тему;
* системну тему Windows;
* акцентний колір.

Налаштування теми зберігати в `config/appsettings.json`.

# 5. Нефункціональні вимоги

## 5.1. UX

Інтерфейс повинен бути:

* зрозумілим для користувача без технічного досвіду;
* мінімалістичним, але функціональним;
* схожим за логікою швидких дій на сучасні скріншотери;
* придатним для роботи без AI;
* без перевантаження складними API-параметрами на головному екрані.

Усі помилки показувати людською мовою.

## 5.2. Продуктивність

Очікування:

* створення скріншота не повинно відчутно зависати;
* AI-запит виконується асинхронно;
* UI не блокується під час мережевого запиту;
* великі зображення за потреби стискаються перед AI-запитом;
* CancellationToken використовується для скасування AI-запитів.

## 5.3. Надійність

Система повинна обробляти:

* відсутність інтернету;
* неправильний API key;
* неправильний endpoint;
* timeout;
* недоступність AI-провайдера;
* помилку збереження файлу;
* недоступну папку;
* конфлікт гарячих клавіш;
* пошкоджений JSON-конфіг;
* відсутні localization-файли.

## 5.4. Безпека і приватність

Вимоги:

* не надсилати скріншот до AI без дії користувача;
* не виконувати автоматичні дії в інших програмах;
* не вводити текст автоматично;
* не логувати API-ключі;
* не логувати вміст скріншотів;
* не логувати приватні prompt-запити;
* дозволити користувачу працювати без AI-ключа;
* архітектурно підготувати перехід до DPAPI або Windows Credential Manager.

У курсовій версії допускається локальне збереження API-ключа в конфігу, але код повинен ізолювати це в окремому сервісі.

## 5.5. Portable-режим

Програма не повинна вимагати інсталяції.

Основна структура:

```text
SmartScreen/
├── SmartScreen.exe
├── config/
│   ├── appsettings.json
│   ├── hotkeys.json
│   ├── ai-providers.json
│   └── prompts.json
├── screenshots/
├── logs/
│   └── app.log
├── localization/
│   ├── uk-UA.json
│   └── en-US.json
└── themes/
    └── themes.json
```

Якщо portable-директорія недоступна для запису, використовувати:

```text
%LOCALAPPDATA%/SmartScreen/
```

# 6. Архітектура

## 6.1. Загальний підхід

Застосунок будується за MVVM:

* `Views` — XAML-вікна та мінімальний code-behind;
* `ViewModels` — стан екранів і команди;
* `Models` — доменні моделі;
* `Services` — бізнес-логіка, робота з ОС, AI, файлами;
* `Commands` — RelayCommand та AsyncRelayCommand;
* `Helpers` — невеликі утиліти без стану;
* `Resources` — стилі, іконки, теми.

## 6.2. Рекомендована структура solution

```text
SmartScreen/
├── SmartScreen.sln
├── SmartScreen.App/
│   ├── Views/
│   ├── ViewModels/
│   ├── Models/
│   ├── Services/
│   │   ├── Interfaces/
│   │   └── Providers/
│   ├── Commands/
│   ├── Helpers/
│   └── Resources/
├── SmartScreen.Tests/
├── config/
├── localization/
├── themes/
├── screenshots/
├── logs/
└── README.md
```

Тести мають покривати щонайменше сервіси конфігурації, prompt-шаблонів, генерацію імен файлів, fallback директорій і санітизацію логів.

## 6.3. Основні сервіси

| Сервіс | Відповідальність |
| --- | --- |
| `IScreenshotService` | створення скріншотів |
| `IImageEditorService` | застосування редагувань до зображення |
| `IAiService` | orchestration AI-запитів |
| `IAiProvider` | конкретна AI-інтеграція |
| `ISettingsService` | читання/запис налаштувань |
| `IHotkeyService` | глобальні клавіші |
| `ITrayService` | системний трей |
| `ILocalizationService` | локалізація |
| `IThemeService` | теми |
| `ILoggingService` | безпечне логування |
| `IStorageService` | директорії, файли, fallback |
| `IClipboardService` | робота з буфером обміну |

## 6.4. Архітектурні принципи

* code-behind тільки для UI-подій, які складно описати через binding;
* сервіси не повинні напряму залежати від конкретних View;
* AI-провайдери не повинні знати про UI;
* конфігурацію читати через сервіс, а не напряму з ViewModel;
* логи проходять через один сервіс із маскуванням секретів;
* помилки сервісів повертаються у вигляді зрозумілих result-моделей або контрольованих винятків;
* мережеві запити завжди мають timeout і cancellation.

# 7. Дані та конфігурація

## 7.1. appsettings.json

Зберігає:

* мову;
* тему;
* папку скріншотів;
* формат збереження;
* поведінку після скріншота;
* параметри редактора;
* активний AI-провайдер;
* ознаку першого запуску.

## 7.2. ai-providers.json

Зберігає:

* назву провайдера;
* endpoint;
* model;
* timeout;
* system prompt;
* API key у курсовій версії.

API key не повинен потрапляти в логи, exception message або UI без маскування.

## 7.3. prompts.json

Зберігає:

* категорії;
* стандартні шаблони;
* користувацькі шаблони;
* ознаку, чи шаблон системний;
* порядок відображення.

## 7.4. hotkeys.json

Зберігає:

* дію;
* комбінацію;
* активність;
* prompt-шаблон для швидкої AI-дії, якщо він є.

# 8. Сценарії використання

## 8.1. Звичайний скріншот

1. Користувач запускає SmartScreen.
2. Натискає кнопку або гарячу клавішу.
3. Обирає режим скріншота.
4. Програма створює зображення.
5. Зображення копіюється в буфер.
6. Відкривається capture workspace (`QuickActionsWindow`) зі швидкими діями.
7. Користувач зберігає, редагує або закриває скріншот.

## 8.2. AI-аналіз

1. Користувач створює скріншот.
2. За потреби редагує його.
3. Натискає «Запитати AI».
4. Обирає prompt-шаблон або вводить власний prompt.
5. Система надсилає відредагований скріншот до активного провайдера.
6. Користувач бачить відповідь в AI-панелі capture workspace.
7. Користувач копіює або зберігає відповідь вручну.

## 8.3. Робота без інтернету

1. Користувач запускає програму без мережі.
2. Скріншоти, редактор, копіювання і збереження працюють.
3. При AI-запиті програма показує: «Немає підключення до інтернету. Скріншот можна зберегти або скопіювати локально».
4. Застосунок не завершується аварійно.

# 9. Критерії приймання

| ID | Критерій | Перевірка |
| --- | --- | --- |
| AC-01 | Застосунок запускається без інсталяції | запуск `.exe` з portable-папки |
| AC-02 | Скріншот всього екрана створюється | файл або clipboard містить зображення |
| AC-03 | Скріншот області створюється | збережена тільки вибрана область |
| AC-04 | Активне вікно знімається коректно | скріншот не містить зайвих областей |
| AC-05 | PNG/JPG зберігаються | файли відкриваються стандартним переглядачем |
| AC-06 | Capture workspace не блокує базовий сценарій | доступні зберегти/копіювати/редагувати/AI |
| AC-07 | Редактор змінює поточний скріншот | фінальна копія містить зміни |
| AC-08 | AI-запит можна скасувати | запит завершується без зависання UI |
| AC-09 | Неправильний API key обробляється | показано зрозуміле повідомлення |
| AC-10 | Без інтернету базові функції працюють | AI показує контрольовану помилку |
| AC-11 | API key не потрапляє в лог | лог перевірено після помилки |
| AC-12 | Пошкоджений JSON не ламає запуск | створюється резервний конфіг або показується відновлення |
| AC-13 | Гарячі клавіші реєструються | дія запускається глобально |
| AC-14 | Конфлікт клавіш показується користувачу | комбінація не зберігається тихо |
| AC-15 | Українська та англійська мови перемикаються | UI оновлює тексти |

# 11. Очікуваний результат

Після реалізації має бути готовий portable WPF-застосунок SmartScreen, який:

* запускається на Windows 10/11;
* створює скріншоти різних типів;
* копіює скріншот у буфер;
* дозволяє швидко зберегти або відредагувати скріншот;
* підтримує AI-аналіз за явною дією користувача;
* має prompt-шаблони;
* має налаштування провайдера, теми, мови й гарячих клавіш;
* працює без інтернету як звичайний скріншотер;
* не зберігає приховану історію;
* не логуває приватні дані;
* має зрозумілу структуру коду для захисту курсової роботи.
