## 3.1. Актуальність

Основна думка:

> Користувачі часто працюють з інформацією на екрані: помилками, текстом, кодом, інтерфейсами, повідомленнями та документами. Звичайні скріншотери дозволяють швидко зафіксувати зображення, однак не допомагають аналізувати його зміст. Інтеграція AI дає змогу перетворити скріншотер на інструмент контекстної допомоги.

## 3.2. Мета роботи

Мета:

```text
Метою курсової роботи є розробка системи SmartScreen для створення, редагування та інтелектуального аналізу скріншотів з можливістю виконання контекстних дій за допомогою зовнішніх AI-сервісів.
```

## 3.3. Об’єкт дослідження

```text
Об’єктом дослідження є процес створення, обробки та аналізу знімків екрана користувача.
```

```text
Предметом дослідження є програмні засоби створення скріншотів, їх редагування та інтеграції з AI-сервісами для виконання контекстних дій.
```

# 4. Розділ 1. Теоретичні основи

Орієнтовний обсяг: **7–9 сторінок**.

Цей розділ пояснює предметну область і обґрунтовує вибір технологій. Код тут не потрібен, максимум короткі приклади або схеми.

## 1.1. Поняття скріншотерів та їх роль у роботі користувача

Обсяг: **1–1,5 сторінки**.

Розкрити:

* що таке скріншот;
* для чого використовують скріншоти;
* роль гарячих клавіш;
* чому важлива швидкість створення скріншота;
* чому звичайного збереження зображення часто недостатньо.

Ключовий висновок: сучасний скріншотер має не тільки фіксувати зображення, а й допомагати користувачу швидко обробити або пояснити його зміст.

## 1.2. Огляд програм-аналогів

Обсяг: **2–2,5 сторінки**.

Розглянути:

* Lightshot;
* ShareX;
* Greenshot;
* Snipping Tool;
* Flameshot.

Рекомендована таблиця:

| Програма | Основні можливості | Переваги | Обмеження |
| --- | --- | --- | --- |
| Lightshot | Скріншот області, простий редактор | швидкість, простота | немає AI-аналізу |
| ShareX | багато режимів, автоматизація | потужний функціонал | складніший для новачків |
| Greenshot | скріншоти, базове редагування | легкість використання | обмежена сучасна автоматизація |
| Snipping Tool | стандартний інструмент Windows | не потребує встановлення | базовий функціонал |
| Flameshot | зручний редактор | якісне редагування | немає вбудованого AI-модуля |

Після таблиці написати висновок: аналоги добре вирішують задачу створення скріншотів, але не дають гнучкого AI-аналізу вмісту екрана.

## 1.3. Використання AI для аналізу зображень

Обсяг: **1,5–2 сторінки**.

Розкрити:

* поняття multimodal AI;
* як AI може аналізувати скріншот;
* які задачі можна автоматизувати;
* обмеження AI-відповідей;
* важливість явної дії користувача перед відправкою зображення.

Приклади задач:

* опис зображення;
* OCR-подібне розпізнавання тексту;
* переклад;
* пояснення помилок;
* пояснення коду;
* аналіз інтерфейсу;
* формування відповіді на основі скріншота.

## 1.4. Контекстні дії та автоматизація

Обсяг: **1–1,5 сторінки**.

Пояснити:

* що таке контекстна дія;
* чим вона відрізняється від звичайної команди;
* чому скріншот є джерелом контексту;
* чому SmartScreen не повинен автоматично керувати іншими програмами.

Приклад:

```text
Якщо на скріншоті показано повідомлення про помилку, контекстною дією буде її пояснення. Якщо на скріншоті є текст іноземною мовою, контекстною дією буде переклад.
```

## 1.5. Вибір технологій

Обсяг: **1,5–2 сторінки**.

Рекомендована таблиця:

| Компонент | Технологія | Обґрунтування |
| --- | --- | --- |
| Мова | C# | зручна для Windows desktop-розробки |
| UI | WPF | підходить для нативного Windows-застосунку |
| Платформа | .NET 9 / готовність до .NET 10 LTS | локальна сумісність і можливість production-оновлення |
| Архітектура | MVVM | розділення UI та логіки |

| AI | provider-архітектура | можливість підключати різні сервіси |
